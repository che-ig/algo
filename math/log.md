floor(log2(i)) = floor(log2(i // 2)) + 1
Это одна из самых красивых и фундаментальных формул в алгоритмах, работающих с двойками.
Давайте разберем её с трёх разных сторон: **через двоичную систему** (самый понятный способ для программиста), **через математику** и **через интервалы**.

---

### 1. Взгляд программиста: Двоичная система и сдвиг битов

Это самое интуитивное объяснение.

Что такое `floor(log2(i))` для целого числа $i$?
Это **номер старшего единичного бита** (считая с нуля) в двоичной записи числа $i$.

_Пример:_
$i = 13$. В двоичной системе: `1101`.
Старший единичный бит стоит на позиции **3** (считая справа налево, начиная с 0: позиции 3, 2, 1, 0).
Значит, `floor(log2(13)) = 3`. (Действительно, $2^3 = 8 \le 13 < 16 = 2^4$).

Теперь посмотрим, что делает операция `i // 2` (целочисленное деление на 2).
В двоичной системе это **побитовый сдвиг вправо на 1 позицию** (`i >> 1`). Мы просто отбрасываем самый младший бит.

_Пример:_
$13$ (`1101`) `// 2` = $6$ (`110`).
Старший единичный бит в числе $6$ (`110`) теперь стоит на позиции **2**.
Значит, `floor(log2(6)) = 2`.

**Вывод:** Когда мы делим число на 2 (сдвигаем вправо), все биты сдвигаются на одну позицию вправо. Следовательно, номер старшего бита **уменьшается ровно на 1**.

Отсюда и формула:
`старший_бит(i) = старший_бит(i // 2) + 1`
или
`floor(log2(i)) = floor(log2(i // 2)) + 1`

---

### 2. Математическое доказательство

Для тех, кто любит строгость.

Пусть $k = \lfloor \log_2(i) \rfloor$.
По определению функции "пол" (floor), это означает, что $k$ — это целое число, удовлетворяющее неравенству:
$$k \le \log_2(i) < k + 1$$

Возведем 2 в степень всех частей неравенства (функция $2^x$ монотонно возрастает, поэтому знаки неравенства сохраняются):
$$2^k \le i < 2^{k+1}$$

Теперь разделим всё неравенство на 2:
$$2^{k-1} \le \frac{i}{2} < 2^k$$

Поскольку $i$ — целое число, результат целочисленного деления $i // 2$ может быть равен либо точно $\frac{i}{2}$ (если $i$ четное), либо $\frac{i-1}{2}$ (если $i$ нечетное).
В обоих случаях, так как мы работаем с целыми числами, строгое неравенство $2^{k-1} \le i // 2 < 2^k$ **остается верным**.

А что означает неравенство $2^{k-1} \le X < 2^k$ для целого числа $X$?
Оно по определению означает, что $\lfloor \log_2(X) \rfloor = k - 1$.

Подставим $X = i // 2$:
$$\lfloor \log_2(i // 2) \rfloor = k - 1$$

Теперь просто выразим $k$:
$$k = \lfloor \log_2(i // 2) \rfloor + 1$$

И так как мы изначально обозначили $k = \lfloor \log_2(i) \rfloor$, получаем искомую формулу:
$$\lfloor \log_2(i) \rfloor = \lfloor \log_2(i // 2) \rfloor + 1$$

### 3. Взгляд через интервалы (ступенчатая функция)

Функция $f(i) = \lfloor \log_2(i) \rfloor$ является ступенчатой. Она сохраняет постоянное значение на интервалах между степенями двойки.

Давайте выпишем эти интервалы:

| Значение $f(i) = \lfloor \log_2(i) \rfloor$ | Диапазон значений $i$                |
| :-----------------------------------------: | :----------------------------------- |
|                    **0**                    | $i \in [1, 1]$ (число 1)             |
|                    **1**                    | $i \in [2, 3]$ (числа 2, 3)          |
|                    **2**                    | $i \in [4, 7]$ (числа 4, 5, 6, 7)    |
|                    **3**                    | $i \in [8, 15]$ (числа от 8 до 15)   |
|                    **4**                    | $i \in [16, 31]$ (числа от 16 до 31) |

**Заметьте закономерность:**
Каждый следующий интервал получается из предыдущего умножением его границ на 2 (и добавлением 1 к верхней границе).
И наоборот: если мы возьмем **любое** число из интервала со значением $K$ и разделим его на 2 (целочисленно), оно **гарантированно попадет** в интервал со значением $K - 1$.

_Пример:_ Возьмем $i = 12$ (оно в интервале $[8, 15]$, где $f(i) = 3$).
Делим на 2: $12 // 2 = 6$.
Число 6 попадает в интервал $[4, 7]$, где $f(6) = 2$.
Видим, что $3 = 2 + 1$. Формула работает безотказно.

---

### 4. Почему это гениально для кода?

Без этой формулы нам пришлось бы вычислять логарифм для каждого числа с нуля, что медленно.
С этой формулой мы можем заполнить весь массив логарифмов **за один линейный проход**, используя уже вычисленные значения:

```python
log_table = [0] * (N + 1)
log_table[1] = 0  # База: log2(1) = 0

for i in range(2, N + 1):
    # Мы уже знаем ответ для i // 2, так как i // 2 < i
    # и мы шли по циклу снизу вверх!
    log_table[i] = log_table[i // 2] + 1
```

**Как это выполняется для $i = 5$:**

1. Нам нужно `log_table[5]`.
2. Мы смотрим на `log_table[5 // 2]`, то есть `log_table[2]`.
3. А `log_table[2]` мы уже вычислили на предыдущих шагах (оно равно `log_table[1] + 1 = 0 + 1 = 1`).
4. Значит, `log_table[5] = 1 + 1 = 2`.

Всё вычисляется за **O(1)** на каждом шаге цикла, что дает общую сложность заполнения массива **O(N)**, что намного быстрее, чем вызывать `math.log2()` $N$ раз.

---

### Резюме

Формула `floor(log2(i)) = floor(log2(i // 2)) + 1` истинна, потому что:

1. **Деление на 2** сдвигает двоичную запись числа вправо на 1 бит.
2. **Логарифм по основанию 2** (с округлением вниз) — это просто индекс этого старшего бита.
3. Сдвиг вправо на 1 позицию уменьшает индекс старшего бита ровно на 1. Следовательно, чтобы получить исходный индекс, нужно к результату для `i // 2` прибавить 1.
