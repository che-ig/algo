## 📜 1. История и происхождение

Алгоритм предложен **Артуром Каном (Arthur B. Kahn)** в **1962 году** в статье _"Topological sorting of large networks"_ (Топологическая сортировка больших сетей), опубликованной в журнале _Communications of the ACM_.

**Контекст эпохи:** В начале 1960-х годов развивались системы управления проектами (PERT, CPM), и требовался эффективный способ определения порядка выполнения задач с зависимостями. Алгоритм Кана стал одним из первых практических решений этой задачи.

---

## 🎯 2. Формальная постановка задачи

**Дано:** Ориентированный граф $G = (V, E)$, где:

- $V$ — множество вершин (задач, модулей, событий)
- $E$ — множество ориентированных рёбер $(u, v)$, означающих, что $u$ должно быть выполнено **до** $v$

**Требуется:** Найти **топологический порядок** — линейное упорядочивание всех вершин $v_1, v_2, \ldots, v_n$ такое, что для каждого ребра $(v_i, v_j) \in E$ выполняется $i < j$.

**Важно:** Топологический порядок существует **только** для ациклических графов (DAG — Directed Acyclic Graph).

---

## 💡 3. Интуитивное объяснение

Представьте, что вы готовите сложное блюдо:

```
[Купить продукты] → [Помыть овощи] → [Нарезать овощи] → [Сварить бульон]
                                                      ↘
[Включить плиту] → [Поставить кастрюлю] ──────────────→ [Добавить овощи] → [Посолить]
```

**Идея алгоритма Кана:**

1. Найдите все действия, которые **ни от кого не зависят** (входящая степень = 0)
2. Выполните их
3. "Удалите" их из графа — уменьшите зависимости тех действий, которые от них зависели
4. Повторяйте, пока все действия не будут выполнены

**Аналогия с университетом:**

- Курсы — вершины
- Пререквизиты — рёбра
- Алгоритм находит порядок сдачи курсов: сначала те, у которых нет пререквизитов, потом те, которые от них зависят, и так далее.

## 📊 4. Пошаговый разбор с примером

Рассмотрим граф:

```
    5 → 0 ← 4
    ↓   ↓   ↓
    2 → 3 → 1
```

Рёбра: (5,2), (5,0), (4,0), (4,1), (2,3), (3,1)

### Шаг 0: Подготовка — подсчёт входящих степеней

```
Вершина | Входящие рёбра | In-degree
--------|----------------|----------
   0    | 5→0, 4→0       |    2
   1    | 4→1, 3→1       |    2
   2    | 5→2            |    1
   3    | 2→3            |    1
   4    | (нет)          |    0  ←
   5    | (нет)          |    0  ←
```

### Шаг 1: Инициализация очереди

Находим все вершины с `in-degree = 0`: это **4** и **5**.

```
Queue: [4, 5]
Result: []
```

### Шаг 2: Обработка вершины 4

Извлекаем **4** из очереди.

```
Queue: [5]
Result: [4]
```

Уменьшаем `in-degree` всех соседей вершины 4:

- Соседи 4: {0, 1}
- `in-degree[0]`: 2 → 1
- `in-degree[1]`: 2 → 1

```
In-degrees: 0→1, 1→1, 2→1, 3→1, 4→0, 5→0
```

Нет новых вершин с `in-degree = 0`.

### Шаг 3: Обработка вершины 5

Извлекаем **5** из очереди.

```
Queue: []
Result: [4, 5]
```

Соседи 5: {2, 0}

- `in-degree[2]`: 1 → 0 ✅ → добавляем в очередь
- `in-degree[0]`: 1 → 0 ✅ → добавляем в очередь

```
Queue: [2, 0]
In-degrees: 0→0, 1→1, 2→0, 3→1, 4→0, 5→0
```

### Шаг 4: Обработка вершины 2

Извлекаем **2**.

```
Queue: [0]
Result: [4, 5, 2]
```

Соседи 2: {3}

- `in-degree[3]`: 1 → 0 ✅ → в очередь

```
Queue: [0, 3]
```

### Шаг 5: Обработка вершины 0

Извлекаем **0**.

```
Queue: [3]
Result: [4, 5, 2, 0]
```

У вершины 0 нет соседей (исходящих рёбер).

### Шаг 6: Обработка вершины 3

Извлекаем **3**.

```
Queue: []
Result: [4, 5, 2, 0, 3]
```

Соседи 3: {1}

- `in-degree[1]`: 1 → 0 ✅ → в очередь

```
Queue: [1]
```

### Шаг 7: Обработка вершины 1

Извлекаем **1**.

```
Queue: []
Result: [4, 5, 2, 0, 3, 1]
```

У вершины 1 нет соседей.

### Шаг 8: Проверка завершения

Очередь пуста. Проверяем: `|Result| = 6 = |V|`. ✅ Все вершины обработаны.

**Итоговый топологический порядок:** `[4, 5, 2, 0, 3, 1]`

**Проверка:**

- 5→0: 5 на позиции 1, 0 на позиции 3 ✅
- 5→2: 5 на позиции 1, 2 на позиции 2 ✅
- 4→0: 4 на позиции 0, 0 на позиции 3 ✅
- 4→1: 4 на позиции 0, 1 на позиции 5 ✅
- 2→3: 2 на позиции 2, 3 на позиции 4 ✅
- 3→1: 3 на позиции 4, 1 на позиции 5 ✅

Все рёбра идут слева направо!

## 📝 5. Псевдокод

```
Алгоритм КАНА(G = (V, E))
Вход: Ориентированный граф G с n вершинами
Выход: Топологический порядок или сообщение о цикле

1. Для каждой вершины v ∈ V:
       in_degree[v] ← 0

2. Для каждого ребра (u, v) ∈ E:
       in_degree[v] ← in_degree[v] + 1

3. Инициализировать пустую очередь Q
4. Для каждой вершины v ∈ V:
       Если in_degree[v] == 0:
           Q.enqueue(v)

5. L ← пустой список  // результат

6. Пока Q не пуста:
       v ← Q.dequeue()
       L.append(v)

       Для каждого соседа w вершины v (т.е. ребро v → w):
           in_degree[w] ← in_degree[w] - 1
           Если in_degree[w] == 0:
               Q.enqueue(w)

7. Если |L| == n:
       Вернуть L  // топологический порядок
   Иначе:
       Вернуть "Граф содержит цикл"
```

## 🔍 6. Анализ сложности

### Временная сложность: **O(V + E)**

| Операция                  | Сложность                                                                       |
| ------------------------- | ------------------------------------------------------------------------------- |
| Инициализация `in_degree` | O(V)                                                                            |
| Подсчёт входящих степеней | O(E) — проход по всем рёбрам                                                    |
| Инициализация очереди     | O(V)                                                                            |
| Основной цикл             | O(V + E) — каждая вершина извлекается 1 раз, каждое ребро просматривается 1 раз |
| Проверка в конце          | O(1)                                                                            |
| **Итого**                 | **O(V + E)**                                                                    |

### Пространственная сложность: **O(V)**

| Структура          | Размер               |
| ------------------ | -------------------- |
| Массив `in_degree` | O(V)                 |
| Очередь Q          | O(V) в худшем случае |
| Список L           | O(V)                 |
| **Итого**          | **O(V)**             |

## ✅ 7. Доказательство корректности

**Теорема:** Алгоритм Кана возвращает топологический порядок тогда и только тогда, когда граф ациклический.

### Часть 1: Если алгоритм вернул порядок, то он корректен

**Доказательство:** Рассмотрим любое ребро $(u, v) \in E$. Вершина $u$ была добавлена в результат раньше, чем $v$, потому что:

- Когда $u$ обрабатывается, `in_degree[v]` уменьшается на 1
- $v$ может попасть в очередь **только** после того, как все её входящие рёбра будут "удалены" (включая ребро от $u$)
- Следовательно, $u$ будет в списке раньше $v$ ✅

### Часть 2: Если граф содержит цикл, алгоритм это обнаружит

**Доказательство:** Пусть в графе есть цикл $C = v_1 \to v_2 \to \ldots \to v_k \to v_1$.

- Каждая вершина цикла имеет **хотя бы одно** входящее ребро изнутри цикла
- Чтобы вершина попала в очередь, её `in_degree` должен стать 0
- Но пока хотя бы одна вершина цикла не обработана, все вершины цикла имеют `in_degree ≥ 1`
- Следовательно, ни одна вершина цикла никогда не попадёт в очередь
- Алгоритм завершится, обработав меньше $n$ вершин ✅

### Часть 3: Если граф ациклический, алгоритм обработает все вершины

**Доказательство (по индукции):**

- **База:** В любом DAG есть хотя бы одна вершина с `in-degree = 0` (иначе был бы цикл)
- **Шаг:** После удаления вершины с `in-degree = 0` и её исходящих рёбер, оставшийся граф остаётся DAG
- По индукции, алгоритм обработает все вершины ✅

## 🛠️ 8. Варианты реализации

### Вариант A: С очередью (стандартный)

```python
from collections import deque

def kahn_bfs(graph, n):
    in_degree = [0] * n
    for u in graph:
        for v in graph[u]:
            in_degree[v] += 1

    queue = deque([i for i in range(n) if in_degree[i] == 0])
    result = []

    while queue:
        u = queue.popleft()
        result.append(u)
        for v in graph[u]:
            in_degree[v] -= 1
            if in_degree[v] == 0:
                queue.append(v)

    return result if len(result) == n else None
```

### Вариант B: С приоритетной очередью (лексикографический порядок)

Если нужен **единственный детерминированный** порядок (например, лексикографический):

```python
import heapq

def kahn_lexicographic(graph, n):
    in_degree = [0] * n
    for u in graph:
        for v in graph[u]:
            in_degree[v] += 1

    heap = [i for i in range(n) if in_degree[i] == 0]
    heapq.heapify(heap)
    result = []

    while heap:
        u = heapq.heappop(heap)
        result.append(u)
        for v in graph[u]:
            in_degree[v] -= 1
            if in_degree[v] == 0:
                heapq.heappush(heap, v)

    return result if len(result) == n else None
```

**Сложность:** O((V + E) log V) из-за операций с кучей.

### Вариант C: Для параллельного выполнения (слои)

Если нужно определить, какие задачи можно выполнять **одновременно**:

```python
def kahn_parallel_layers(graph, n):
    in_degree = [0] * n
    for u in graph:
        for v in graph[u]:
            in_degree[v] += 1

    current_layer = [i for i in range(n) if in_degree[i] == 0]
    layers = []

    while current_layer:
        layers.append(current_layer)
        next_layer = []
        for u in current_layer:
            for v in graph[u]:
                in_degree[v] -= 1
                if in_degree[v] == 0:
                    next_layer.append(v)
        current_layer = next_layer

    return layers if sum(len(layer) for layer in layers) == n else None
```

**Пример вывода:**

```
Layer 0: [4, 5]  # Можно выполнить параллельно
Layer 1: [2, 0]  # Можно выполнить параллельно
Layer 2: [3]
Layer 3: [1]
```

## 🔄 9. Модификации и расширения

### 9.1. Восстановление всех возможных топологических порядков

Алгоритм Кана можно модифицировать для генерации **всех** топологических порядков с помощью backtracking:

```python
def all_topological_sorts(graph, n):
    in_degree = [0] * n
    for u in graph:
        for v in graph[u]:
            in_degree[v] += 1

    result = []
    current = []
    visited = [False] * n

    def backtrack():
        for i in range(n):
            if not visited[i] and in_degree[i] == 0:
                # Выбираем вершину i
                visited[i] = True
                current.append(i)
                for v in graph[i]:
                    in_degree[v] -= 1

                backtrack()

                # Откат
                visited[i] = False
                current.pop()
                for v in graph[i]:
                    in_degree[v] += 1

        if len(current) == n:
            result.append(current[:])

    backtrack()
    return result
```

### 9.2. Нахождение критического пути (Critical Path Method)

В управлении проектами алгоритм Кана используется для нахождения **критического пути** — самой длинной цепочки задач, определяющей минимальное время выполнения проекта.

### 9.3. Топологическая сортировка с весами

Если рёбра имеют веса (например, время выполнения задачи), можно модифицировать алгоритм для нахождения **раннего/позднего времени начала** каждой задачи.

## 🆚 10. Сравнение с алгоритмом Тарьяна (DFS)

| Критерий               | Алгоритм Кана (BFS)          | Алгоритм Тарьяна (DFS)       |
| ---------------------- | ---------------------------- | ---------------------------- |
| **Подход**             | Итеративный, с очередью      | Рекурсивный, со стеком       |
| **Время**              | O(V + E)                     | O(V + E)                     |
| **Память**             | O(V)                         | O(V)                         |
| **Обнаружение циклов** | Автоматическое               | Требует 3-цветной маркировки |
| **Параллелизм**        | Легко получить слои          | Сложно                       |
| **Глубокие графы**     | Нет риска переполнения стека | Риск Stack Overflow          |
| **Подготовка**         | Нужен подсчёт in-degree      | Не нужен                     |
| **Обратный порядок**   | Нужно инвертировать          | Естественный (post-order)    |

**Когда выбрать Кан:**

- Нужна проверка на циклы
- Нужны слои для параллелизма
- Граф очень глубокий
- Пишете на языке без оптимизации хвостовой рекурсии

**Когда выбрать Тарьяна (DFS):**

- Уже используете DFS для другой задачи
- Граф задан так, что подсчёт in-degree неудобен
- Нужен обратный топологический порядок

## 🎓 12. Типичные ошибки при реализации

### Ошибка 1: Забыть проверить все вершины

```python
# ❌ Неправильно
in_degree = {u: 0 for u in graph}  # Пропускает вершины без исходящих рёбер

# ✅ Правильно
in_degree = {v: 0 for v in all_vertices}
```

### Ошибка 2: Не обработать вершины без соседей

```python
# ❌ Неправильно
for neighbor in graph[u]:  # KeyError, если u нет в graph
    in_degree[neighbor] -= 1

# ✅ Правильно
for neighbor in graph.get(u, []):
    in_degree[neighbor] -= 1
```

### Ошибка 3: Использовать список вместо deque

```python
# ❌ Медленно: O(n) для pop(0)
queue = [0, 1, 2]
u = queue.pop(0)

# ✅ Быстро: O(1)
from collections import deque
queue = deque([0, 1, 2])
u = queue.popleft()
```

## 🏁 13. Заключение

Алгоритм Кана — это **элегантный, эффективный и практичный** алгоритм для топологической сортировки. Его ключевые преимущества:

✅ **Простота** — легко понять и реализовать  
✅ **Эффективность** — O(V + E) по времени и памяти  
✅ **Обнаружение циклов** — встроенная проверка  
✅ **Параллелизм** — легко получить слои задач  
✅ **Устойчивость** — нет риска переполнения стека

Алгоритм широко используется в реальных системах: от компиляторов и сборщиков до планировщиков задач и менеджеров пакетов. Понимание этого алгоритма — обязательный навык для любого программиста, работающего с графами или зависимостями.
