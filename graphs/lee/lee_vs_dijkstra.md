# Алгоритм Ли vs Дейкстра при одинаковых весах рёбер

## 🎯 Краткий ответ

**При одинаковых весах рёбер алгоритм Ли (BFS) практически всегда предпочтительнее алгоритма Дейкстры.**

Причина: алгоритм Ли — это **специализированная версия** Дейкстры для случая единичных весов. Дейкстра в этом случае делает ту же работу, но с дополнительными накладными расходами на приоритетную очередь.

---

## 📚 Теоретическое обоснование

### Ключевое наблюдение

Алгоритм Дейкстры использует **приоритетную очередь (min-heap)**, чтобы всегда извлекать вершину с минимальным расстоянием. Но если все рёбра имеют вес 1, то:

- Все вершины на расстоянии `d` от старта имеют **одинаковый приоритет**
- Очередь с приоритетами вырождается в **FIFO-очередь**
- Вершины обрабатываются **ровно в том же порядке**, что и в BFS

**Вывод:** При единичных весах Дейкстра делает **ту же самую работу**, что и BFS, но тратит дополнительные ресурсы на поддержание структуры приоритетной очереди.

---

## ⏱️ Сравнение производительности

### Временная сложность

| Алгоритм                           | Формула             | Пояснение                                                   |
| ---------------------------------- | ------------------- | ----------------------------------------------------------- |
| **Алгоритм Ли (BFS)**              | $O(V + E)$          | Каждая вершина и ребро обрабатываются 1 раз                 |
| **Дейкстра с бинарной кучей**      | $O((V + E) \log V)$ | Каждая операция с кучей — $O(\log V)$                       |
| **Дейкстра с Фибоначчиевой кучей** | $O(V \log V + E)$   | Теоретически лучше, но на практике медленнее из-за констант |

### Почему Дейкстра медленнее?

**Алгоритм Ли (обычная очередь):**

```python
queue.append(neighbor)      # O(1)
current = queue.popleft()   # O(1)
```

**Дейкстра (приоритетная очередь):**

```python
heapq.heappush(pq, (dist, neighbor))  # O(log V)
dist, current = heapq.heappop(pq)     # O(log V)
```

**Разница:** На каждой операции Дейкстра тратит **$O(\log V)$** вместо **$O(1)$**.

### Практический пример

Для сетки 100×100 (V = 10 000, E ≈ 40 000):

| Операция                  | Алгоритм Ли    | Дейкстра (binary heap)      |
| ------------------------- | -------------- | --------------------------- |
| Добавление в очередь      | 1 такт         | ~14 тактов ($\log_2 10000$) |
| Извлечение из очереди     | 1 такт         | ~14 тактов                  |
| **Итого на 40 000 рёбер** | ~40 000 тактов | ~560 000 тактов             |

**Разница в скорости:** Дейкстра может быть в **10-20 раз медленнее** на практике.

## 💾 Сравнение затрат памяти

### Структуры данных

| Структура         | Алгоритм Ли                          | Дейкстра                                                   |
| ----------------- | ------------------------------------ | ---------------------------------------------------------- |
| Очередь           | `deque` — ~8 байт/элемент            | `list` (heap) — ~8 байт/элемент + кортежи `(dist, vertex)` |
| Расстояния        | `list[list[int]]` — 4 байта/клетка   | `dict` или `list[list[int]]` — 4+ байта/клетка             |
| Предки            | `list[list[Point]]` — 16 байт/клетка | `list[list[Point]]` — 16 байт/клетка                       |
| **Дополнительно** | —                                    | Кортежи `(dist, vertex)` в куче: +8 байт/элемент           |

### Подсчёт памяти для сетки 1000×1000

**Алгоритм Ли:**

```
distance: 1000 × 1000 × 4 байта = 4 МБ
parent:   1000 × 1000 × 16 байт = 16 МБ
queue:    до 1 000 000 × 8 байт = 8 МБ (в худшем случае)
─────────────────────────────────────────
ИТОГО: ~28 МБ
```

**Дейкстра:**

```
distance: 1000 × 1000 × 4 байта = 4 МБ
parent:   1000 × 1000 × 16 байт = 16 МБ
heap:     до 1 000 000 × 16 байт = 16 МБ (кортежи dist + vertex)
─────────────────────────────────────────
ИТОГО: ~36 МБ
```

**Разница:** Дейкстра тратит на **~30% больше памяти** из-за хранения пар `(distance, vertex)` в куче.

## 🔬 Почему алгоритм Ли быстрее на практике?

### 1. **Простая очередь vs приоритетная очередь**

- `deque` — это двусвязный список с O(1) операциями
- `heapq` — это бинарная куча с O(log n) операциями
- На каждом шаге Дейкстра делает **в 10-20 раз больше работы**

### 2. **Кэше-дружественность**

- Алгоритм Ли обрабатывает вершины **последовательно** (FIFO)
- Дейкстра обращается к вершинам **случайно** (по приоритету)
- Современные CPU лучше предсказывают последовательный доступ → меньше cache misses

### 3. **Меньше аллокаций памяти**

- Алгоритм Ли хранит только вершины в очереди
- Дейкстра создаёт кортежи `(distance, vertex)` для каждого элемента в куче
- Больше аллокаций → больше нагрузки на GC (в Python)

### 4. **Нет избыточных обновлений**

В Дейкстре одна и та же вершина может **несколько раз** добавляться в кучу с разными расстояниями (lazy deletion). В алгоритме Ли вершина добавляется в очередь **ровно один раз**.

## 🧪 Мысленный эксперимент

Представьте сетку 10×10, старт в (0,0), цель в (9,9):

**Алгоритм Ли (BFS):**

```
Шаг 1: очередь = [(0,0)]
Шаг 2: очередь = [(0,1), (1,0)]
Шаг 3: очередь = [(0,2), (1,1), (2,0)]
...
Каждая вершина обрабатывается 1 раз, каждая добавляется 1 раз.
```

**Дейкстра:**

```
Шаг 1: heap = [(0, (0,0))]
Шаг 2: heap = [(1, (0,1)), (1, (1,0))]
Шаг 3: heap = [(2, (0,2)), (2, (1,1)), (2, (2,0))]
...
Каждая вершина обрабатывается 1 раз, но:
- Каждое добавление: O(log n)
- Каждое извлечение: O(log n)
- Хранение кортежей: +память
```

**Результат:** Дейкстра делает **ту же работу**, но тратит **в 10-20 раз больше времени** на операции с кучей.

---

## 🎯 Когда всё-таки использовать Дейкстру?

Алгоритм Дейкстра предпочтительнее, если:

1. **Веса рёбер разные**
   - Болото vs дорога
   - Пробки на дорогах
   - Разная стоимость перехода между зонами

2. **Граф не является сеткой**
   - Дорожная сеть городов
   - Социальные графы
   - Сети коммуникаций

3. **Нужна гибкость**
   - Вы не знаете заранее, будут ли веса одинаковыми
   - Код может использоваться в разных сценариях

4. **Нужны дополнительные возможности**
   - Поиск k-кратчайших путей
   - Модификации алгоритма (A*, D*)

## 📝 Итог

### При одинаковых весах рёбер:

| Критерий               | Рекомендация                            |
| ---------------------- | --------------------------------------- |
| **Производительность** | 🏆 **Алгоритм Ли** (в 10-20× быстрее)   |
| **Память**             | 🏆 **Алгоритм Ли** (на 30% меньше)      |
| **Простота**           | 🏆 **Алгоритм Ли** (проще в реализации) |
| **Гибкость**           | 🏆 **Дейкстра** (поддерживает веса)     |

### Золотое правило:

> **Если все веса одинаковы → используйте алгоритм Ли (BFS).**  
> **Если веса разные → используйте Дейкстру или A\*.**

Алгоритм Ли — это **оптимизированная версия Дейкстры** для случая единичных весов. Использовать Дейкстру при одинаковых весах — это как **ехать на такси по прямой дороге**, когда можно идти пешком: быстрее, дешевле и проще.
