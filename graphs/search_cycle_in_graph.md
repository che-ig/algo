# Лучший алгоритм для поиска цикла в графе

Короткий ответ: **универсального "лучшего" алгоритма нет**. Выбор зависит от типа графа и того, что именно нужно найти. Но есть **стандартные решения**, которые считаются оптимальными в своих категориях.

---

## 🎯 Сначала определимся с задачей

"Поиск цикла" может означать разное:

| Задача                                  | Сложность                               |
| --------------------------------------- | --------------------------------------- |
| Есть ли **хотя бы один** цикл?          | O(V + E)                                |
| Найти **любой** цикл и вывести его      | O(V + E)                                |
| Найти **все** простые циклы             | O((V + E)(C + 1)), где C — число циклов |
| Найти **все** сильно связные компоненты | O(V + E)                                |
| Онлайн-проверка при добавлении рёбер    | O(E · α(V))                             |

---

## 📐 Для ориентированных графов

### 1. DFS с 3-цветной маркировкой ⭐ (золотой стандарт)

**Идея:** Раскрашиваем вершины в три цвета:

- 🟦 **Белый** — не посещён
- 🟨 **Серый** — в процессе обхода (в стеке рекурсии)
- 🟩 **Чёрный** — полностью обработан

Если DFS натыкается на **серую** вершину — найден цикл (back edge).

**Сложность:** O(V + E) по времени, O(V) по памяти.

```python
from enum import IntEnum

class Color(IntEnum):
    WHITE = 0  # не посещена
    GRAY = 1   # в стеке рекурсии
    BLACK = 2  # обработана

def has_cycle_directed(graph: dict[int, list[int]]) -> bool:
    """Проверяет наличие цикла в ориентированном графе через DFS."""
    color: dict[int, Color] = {v: Color.WHITE for v in graph}

    def dfs(u: int) -> bool:
        color[u] = Color.GRAY
        for v in graph.get(u, []):
            if color[v] == Color.GRAY:
                return True  # нашли обратное ребро → цикл
            if color[v] == Color.WHITE and dfs(v):
                return True
        color[u] = Color.BLACK
        return False

    return any(
        color[v] == Color.WHITE and dfs(v)
        for v in graph
    )
```

**Плюсы:**

- Простой и быстрый
- Можно легко модифицировать для **восстановления самого цикла**
- Работает за один проход

**Минусы:**

- Рекурсия → риск переполнения стека на глубоких графах
- Нужно явно хранить граф

### 2. Алгоритм Кана (через топологическую сортировку)

**Идея:** Если после работы алгоритма Кана остаются необработанные вершины — в графе есть цикл.

```python
from collections import deque

def has_cycle_kahn(graph: dict[int, list[int]]) -> bool:
    """Проверяет наличие цикла через алгоритм Кана."""
    # Собираем все вершины
    vertices = set(graph.keys())
    for neighbors in graph.values():
        vertices.update(neighbors)

    # Считаем входящие степени
    in_degree = {v: 0 for v in vertices}
    for u in graph:
        for v in graph[u]:
            in_degree[v] += 1

    # Очередь вершин с нулевой степенью
    queue = deque(v for v, d in in_degree.items() if d == 0)
    processed = 0

    while queue:
        u = queue.popleft()
        processed += 1
        for v in graph.get(u, []):
            in_degree[v] -= 1
            if in_degree[v] == 0:
                queue.append(v)

    return processed != len(vertices)
```

**Плюсы:**

- Итеративный → нет риска переполнения стека
- Даёт **топологический порядок** как бонус
- Легко получить вершины, участвующие в цикле

**Минусы:**

- Требует подсчёта входящих степеней
- Не даёт сам цикл (только факт его наличия)

---

### 3. Алгоритм Тарьяна для SCC

**Идея:** Находит **сильно связные компоненты**. Если хотя бы одна SCC содержит >1 вершины (или петлю) — в графе есть цикл.

**Сложность:** O(V + E)

**Плюсы:**

- Находит **все** циклические структуры сразу
- Полезен для анализа зависимостей

**Минусы:**

- Избыточен, если нужно просто проверить наличие цикла
- Сложнее в реализации

## 📐 Для неориентированных графов

### 1. DFS с отслеживанием родителя ⭐ (золотой стандарт)

**Идея:** Запускаем DFS. Если встречаем посещённую вершину, которая **не является родителем** текущей — нашли цикл.

```python
def has_cycle_undirected(graph: dict[int, list[int]]) -> bool:
    """Проверяет наличие цикла в неориентированном графе."""
    visited: set[int] = set()

    def dfs(u: int, parent: int | None) -> bool:
        visited.add(u)
        for v in graph.get(u, []):
            if v not in visited:
                if dfs(v, u):
                    return True
            elif v != parent:
                return True  # нашли цикл
        return False

    return any(
        v not in visited and dfs(v, None)
        for v in graph
    )
```

**Сложность:** O(V + E)

**Плюсы:**

- Простой
- Работает за один проход

**Минусы:**

- Рекурсия
- Не работает для мультиграфов без модификации

### 2. Union-Find (СНМ — система непересекающихся множеств) ⭐⭐

**Идея:** Для каждого ребра `(u, v)` проверяем, принадлежат ли `u` и `v` одному множеству. Если да — цикл. Иначе объединяем множества.

```python
class UnionFind:
    def __init__(self, n: int) -> None:
        self.parent = list(range(n))
        self.rank = [0] * n

    def find(self, x: int) -> int:
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]  # path compression
            x = self.parent[x]
        return x

    def union(self, x: int, y: int) -> bool:
        """Объединяет множества. Возвращает False, если уже в одном множестве (цикл)."""
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return False
        if self.rank[rx] < self.rank[ry]:
            rx, ry = ry, rx
        self.parent[ry] = rx
        if self.rank[rx] == self.rank[ry]:
            self.rank[rx] += 1
        return True

def has_cycle_undirected_uf(edges: list[tuple[int, int]], n: int) -> bool:
    """Проверяет наличие цикла через Union-Find."""
    uf = UnionFind(n)
    for u, v in edges:
        if not uf.union(u, v):
            return True
    return False
```

**Сложность:** O(E · α(V)), где α — обратная функция Аккермана (практически O(1)).

**Плюсы:**

- **Идеален для онлайн-режима** — можно проверять цикл при добавлении рёбер
- Простая итеративная реализация
- Отлично работает с рёбрами как с потоком данных

**Минусы:**

- Требует, чтобы вершины были пронумерованы `0..n-1`
- Не находит сам цикл, только факт

## 🏆 Что выбрать? Практические рекомендации

### Для ориентированного графа:

| Ситуация                                | Лучший выбор                    |
| --------------------------------------- | ------------------------------- |
| Просто проверить наличие цикла          | **DFS с 3-цветной маркировкой** |
| Нужен топологический порядок + проверка | **Алгоритм Кана**               |
| Глубокий граф, боитесь Stack Overflow   | **Алгоритм Кана** (итеративный) |
| Нужно найти все циклические компоненты  | **Тарьян SCC**                  |
| Нужно восстановить сам цикл             | **DFS с 3-цветной маркировкой** |

### Для неориентированного графа:

| Ситуация                              | Лучший выбор                     |
| ------------------------------------- | -------------------------------- |
| Граф уже построен, одна проверка      | **DFS с отслеживанием родителя** |
| Рёбра добавляются по одному (онлайн)  | **Union-Find** ⭐⭐⭐            |
| Алгоритм Краскала (минимальный остов) | **Union-Find**                   |
| Огромный граф, нужна скорость         | **Union-Find**                   |

## 🔥 Как восстановить сам цикл (ориентированный граф)

Часто нужно не просто "да/нет", а **вывести сам цикл**. Вот модификация DFS:

```python
def find_cycle_directed(graph: dict[int, list[int]]) -> list[int] | None:
    """Находит любой цикл в ориентированном графе и возвращает его."""
    color: dict[int, Color] = {v: Color.WHITE for v in graph}
    parent: dict[int, int | None] = {}

    def dfs(u: int) -> list[int] | None:
        color[u] = Color.GRAY
        for v in graph.get(u, []):
            if color[v] == Color.GRAY:
                # Нашли цикл: восстанавливаем путь от v до u через parent
                cycle = [v, u]
                cur = parent.get(u)
                while cur is not None and cur != v:
                    cycle.append(cur)
                    cur = parent.get(cur)
                cycle.reverse()
                return cycle
            if color[v] == Color.WHITE:
                parent[v] = u
                result = dfs(v)
                if result is not None:
                    return result
        color[u] = Color.BLACK
        return None

    for v in graph:
        if color[v] == Color.WHITE:
            parent[v] = None
            result = dfs(v)
            if result is not None:
                return result
    return None
```

## 🎓 Итоговая рекомендация

Если нужно **одно простое решение на все случаи**:

- **Ориентированный граф** → **DFS с 3-цветной маркировкой** (или Кан, если боитесь рекурсии)
- **Неориентированный граф** → **DFS с отслеживанием родителя**
- **Онлайн-добавление рёбер** → **Union-Find** (безальтернативно)

Все эти алгоритмы работают за **O(V + E)** и считаются оптимальными — быстрее теоретически нельзя, так как нужно хотя бы один раз посмотреть на каждое ребро.

**Золотое правило:** Начните с DFS. Если DFS не подходит (онлайн, глубокий граф, мультиграф) — переходите к специализированным алгоритмам.
