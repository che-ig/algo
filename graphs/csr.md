# CSR (Compressed Sparse Row) — подробное объяснение

## 🎯 Какую проблему решает CSR?

Представьте, что у вас есть граф с **1 000 000 вершин** и **3 000 000 рёбер**. Это типичный размер для реальных задач (социальные сети, веб-графы, дорожные сети).

### ❌ Проблема обычного списка смежности

```python
# Обычное представление в Python:
graph = {
    0: [5, 12, 78, 103],
    1: [0, 42, 99],
    2: [7, 15],
    ...
}
```

**Проблемы:**

1. **Миллион маленьких списков** — каждый `list` в Python — это отдельный объект с заголовком (~56 байт) + массив указателей
2. **Фрагментация памяти** — списки разбросаны по куче, CPU не может предсказать, где лежат данные
3. **Указатели на указатели** — чтобы получить соседа, нужно: `dict → list → элемент → объект-сосед`
4. **Плохая локальность** — соседи одной вершины могут лежать в разных местах памяти

**Результат:** при обходе графа ~60-80% обращений к памяти — **cache miss**. CPU простаивает.

---

## 💡 Идея CSR на пальцах

Представьте **библиотеку**:

- У вас есть **полки** (вершины графа)
- На каждой полке — **книги** (соседи вершины)
- Книг разное количество на разных полках

### ❌ Плохой способ (как обычный список смежности)

Каждая книга — в своём отдельном шкафу в разных концах библиотеки. Чтобы найти все книги с полки №5, нужно бегать по всей библиотеке.

### ✅ Хороший способ (как CSR)

**Все книги всех полок стоят в одном длинном ряду**, а у каждой полки есть **табличка с номером**, откуда начинаются её книги.

```
Полка 0: "Мои книги начинаются с позиции 0"
Полка 1: "Мои книги начинаются с позиции 4"
Полка 2: "Мои книги начинаются с позиции 7"
...

[Книги полки 0][Книги полки 1][Книги полки 2]...
← 4 книги →← 3 книги →← 2 книги →
```

Теперь, чтобы взять все книги полки №1, вы просто идёте к позиции 4 и берёте 3 книги подряд. **Один поход, всё рядом.**

## 📊 Пошаговое построение CSR

### Шаг 0: Исходный граф

Рассмотрим ориентированный граф из 5 вершин:

```
        ┌──→ 1 ──→ 3
        │         ↑
  0 ────┤         │
        │         │
        └──→ 2 ───┘
              │
              └──→ 4
```

Список смежности:

```
Вершина 0: [1, 2]
Вершина 1: [3]
Вершина 2: [3, 4]
Вершина 3: []
Вершина 4: [0]
```

### Шаг 1: Матрица смежности (для наглядности)

```
      0  1  2  3  4    ← столбцы (куда идёт ребро)
    ┌─────────────────┐
  0 │ 0  1  1  0  0 │  ← строка 0: рёбра из вершины 0
  1 │ 0  0  0  1  0 │  ← строка 1: рёбра из вершины 1
  2 │ 0  0  0  1  1 │  ← строка 2: рёбра из вершины 2
  3 │ 0  0  0  0  0 │  ← строка 3: рёбер нет
  4 │ 1  0  0  0  0 │  ← строка 4: ребро в вершину 0
    └─────────────────┘
```

**Проблема матрицы:** 25 ячеек, но только 6 рёбер. Для графа с 1 млн вершин — **1 триллион ячеек**, из которых 99.9997% — нули.

### Шаг 2: Выписываем все ненулевые элементы по строкам

Идём по строкам матрицы сверху вниз, выписываем **только единицы** (или индексы столбцов, где стоят единицы):

```
Строка 0: 1 на позициях [1, 2]      → записываем: 1, 2
Строка 1: 1 на позиции  [3]         → записываем: 3
Строка 2: 1 на позициях [3, 4]      → записываем: 3, 4
Строка 3: нет единиц                → ничего не записываем
Строка 4: 1 на позиции  [0]         → записываем: 0
```

Складываем всё в **один длинный массив**:

```
column_indices = [1, 2, 3, 3, 4, 0]
                  └─┬─┘ └┬┘ └─┬─┘      └┬┘
                    │    │     │         │
                 строка 0  1   2        4
```

### Шаг 3: Строим массив offsets (указателей на начало)

Теперь нам нужно знать, **где в `column_indices` начинается каждая строка**.

Считаем количество элементов в каждой строке:

```
Строка 0: 2 элемента
Строка 1: 1 элемент
Строка 2: 2 элемента
Строка 3: 0 элементов
Строка 4: 1 элемент
```

Строим **префиксные суммы** (cumulative sum):

```
offsets[0] = 0                           (начало строки 0)
offsets[1] = 0 + 2 = 2                   (начало строки 1)
offsets[2] = 2 + 1 = 3                   (начало строки 2)
offsets[3] = 3 + 2 = 5                   (начало строки 3)
offsets[4] = 5 + 0 = 5                   (начало строки 4)
offsets[5] = 5 + 1 = 6                   (конец строки 4 = общее число рёбер)
```

```
offsets = [0, 2, 3, 5, 5, 6]
           ↑  ↑  ↑  ↑  ↑  ↑
           │  │  │  │  │  └─ конец (всего 6 рёбер)
           │  │  │  │  └──── строка 4 начинается на позиции 5
           │  │  │  └─────── строка 3 начинается на позиции 5 (пустая!)
           │  │  └────────── строка 2 начинается на позиции 3
           │  └───────────── строка 1 начинается на позиции 2
           └──────────────── строка 0 начинается на позиции 0
```

**Важно:** в `offsets` всегда на **1 элемент больше**, чем вершин. Последний элемент — это общее количество рёбер.

## 🔍 Смысл каждого массива

### 1. `offsets` (или `row_ptr`, `indptr`)

**Что хранит:** Индекс в массиве `column_indices`, с которого начинается список соседей вершины `i`.

**Смысл:** "Если хочешь узнать соседей вершины `i`, начни читать `column_indices` с позиции `offsets[i]` и закончи на `offsets[i+1]`."

**Размер:** `V + 1` элементов (где V — число вершин).

**Аналогия:** Номера страниц в книге глав. Глава 1 начинается со страницы `offsets[1]`, глава 2 — с `offsets[2]`, и т.д.

### 2. `column_indices` (или `indices`, `col_idx`)

**Что хранит:** Все соседи всех вершин, **выписанные подряд**.

**Смысл:** "Это плоский список всех рёбер графа, сгруппированный по источникам."

**Размер:** `E` элементов (где E — число рёбер).

**Аналогия:** Все книги библиотеки, стоящие в одном длинном ряду.

### 3. `values` (опционально, для взвешенных графов)

**Что хранит:** Веса рёбер, **параллельно** `column_indices`.

**Смысл:** "`values[k]` — это вес ребра от вершины `i` к вершине `column_indices[k]`."

**Размер:** `E` элементов.

```
column_indices = [1,  2,  3,  3,  4,  0]
values         = [10, 5,  7,  2,  8,  3]
                  ↑    ↑   ↑   ↑   ↑   ↑
                  └────┴───┴───┴───┴───┘
                  веса тех же самых рёбер
```

## 🛠️ Как читать данные из CSR

### Получить всех соседей вершины `v`:

```python
def get_neighbors(offsets, column_indices, v):
    """Возвращает список соседей вершины v."""
    start = offsets[v]
    end = offsets[v + 1]
    return column_indices[start:end]

# Пример:
neighbors_of_2 = get_neighbors(offsets, column_indices, 2)
# start = offsets[2] = 3
# end   = offsets[3] = 5
# column_indices[3:5] = [3, 4]
# Результат: [3, 4] ✅
```

### Иллюстрация чтения:

```
Хотим узнать соседей вершины 2:

offsets:        [0,  2,  3,  5,  5,  6]
                      ↑   ↑
                      │   │
                 start=3  end=5

column_indices: [1,  2,  3,  3,  4,  0]
                      ↑───↑
                      │   │
                   берём [3:5] = [3, 4]

Ответ: соседи вершины 2 — это [3, 4] ✅
```

### Проверить, есть ли ребро `u → v`:

```python
def has_edge(offsets, column_indices, u, v):
    """Проверяет наличие ребра u → v."""
    start = offsets[u]
    end = offsets[u + 1]
    # Ищем v в срезе column_indices[start:end]
    return v in column_indices[start:end]

# Если column_indices отсортирован — можно использовать бинарный поиск:
import bisect
def has_edge_fast(offsets, column_indices, u, v):
    start = offsets[u]
    end = offsets[u + 1]
    idx = bisect.bisect_left(column_indices, v, start, end)
    return idx < end and column_indices[idx] == v
```

## 🚶 Пример: обход графа (BFS) на CSR

```python
from collections import deque

def bfs_csr(offsets, column_indices, start, n_vertices):
    """BFS на CSR-представлении графа."""
    distances = [-1] * n_vertices
    distances[start] = 0

    queue = deque([start])

    while queue:
        v = queue.popleft()

        # 🔑 Ключевая операция: получаем соседей через offsets
        for i in range(offsets[v], offsets[v + 1]):
            neighbor = column_indices[i]
            if distances[neighbor] == -1:
                distances[neighbor] = distances[v] + 1
                queue.append(neighbor)

    return distances

# Запуск:
offsets = [0, 2, 3, 5, 5, 6]
column_indices = [1, 2, 3, 3, 4, 0]
print(bfs_csr(offsets, column_indices, start=0, n_vertices=5))
# Результат: [0, 1, 1, 2, 2]
#            │  │  │  │  │
#            │  │  │  │  └─ вершина 4 на расстоянии 2
#            │  │  │  └──── вершина 3 на расстоянии 2
#            │  │  └─────── вершина 2 на расстоянии 1
#            │  └────────── вершина 1 на расстоянии 1
#            └───────────── вершина 0 (старт) на расстоянии 0
```

## 📐 Почему CSR кеш-френдли?

### Сравнение в памяти:

**Обычный список смежности (Python):**

```
Куча Python:
┌────────────────────┐
│ dict object (0x1000)│──→ list (0x2000) ──→ [int(1), int(2)] (0x3000, 0x3010)
└────────────────────┘
         │
         └──→ list (0x4000) ──→ [int(3)] (0x5000)

Каждый int — отдельный объект ~28 байт
Каждый list — отдельный объект ~56 байт
Всё разбросано по куче
```

**CSR (numpy):**

```
Непрерывная память:
┌──────────────────────────────────────────────┐
│ offsets:        [0, 2, 3, 5, 5, 6]           │ ← 24 байта подряд
│ column_indices: [1, 2, 3, 3, 4, 0]           │ ← 24 байта подряд
└──────────────────────────────────────────────┘

Всё лежит рядом. Одна кеш-линия (64 байта) покрывает оба массива целиком.
```

### Что происходит при обходе:

**Обычный список:**

```
1. Читаем dict[2]           → cache miss (dict в другом месте памяти)
2. Читаем list object       → cache miss (list в третьем месте)
3. Читаем int(3)            → cache miss (int — объект в куче)
4. Читаем int(4)            → cache miss

Итого: 4 cache miss на 2 соседей
```

**CSR:**

```
1. Читаем offsets[2]        → cache hit (массив в кеше)
2. Читаем offsets[3]        → cache hit (рядом с offsets[2])
3. Читаем column_indices[3] → cache hit (массив в кеше)
4. Читаем column_indices[4] → cache hit (рядом с предыдущим)

Итого: 0 cache miss на 2 соседей
```

## 🔄 Варианты CSR

### CSC (Compressed Sparse Column)

То же самое, но **сжатие по столбцам**, а не по строкам.

```
CSR: удобно получать ИСХОДЯЩИЕ рёбра (соседей вершины)
CSC: удобно получать ВХОДЯЩИЕ рёбра (кто зависит от вершины)
```

Для CSC:

- `offsets` хранит начало списка **входящих** рёбер для каждой вершины
- `row_indices` хранит источники этих рёбер

### CSR с отсортированными соседями

Если `column_indices` внутри каждого блока отсортированы:

```
column_indices = [1, 2,  3,  3, 4,  0]
                  ↑───↑   ↑   ↑───↑   ↑
                   сорти-  сорти-  сорти-
                   ровано  ровано  ровано
```

Тогда проверка наличия ребра работает за **O(log deg(v))** через бинарный поиск.

| Операция                     | CSR                                | Список смежности | Матрица смежности  |
| ---------------------------- | ---------------------------------- | ---------------- | ------------------ |
| Получить соседей вершины `v` | $O(\deg(v))$                       | $O(\deg(v))$     | $O(V)$             |
| Проверить ребро `u → v`      | $O(\deg(u))$ или $O(\log \deg(u))$ | $O(\deg(u))$     | $O(1)$             |
| Память                       | $O(V + E)$                         | $O(V + E)$       | $O(V^2)$           |
| Кеш-френдли                  | ✅✅✅                             | ❌               | ✅✅ (для плотных) |
| Добавить ребро               | ❌ Дорого                          | ✅ $O(1)$        | ✅ $O(1)$          |
| Удалить ребро                | ❌ Дорого                          | ✅ $O(\deg)$     | ✅ $O(1)$          |

## 🎯 Итог

**CSR** — это способ хранить разреженный граф (или матрицу) в **трёх плоских массивах**:

| Массив           | Размер  | Смысл                                                                    |
| ---------------- | ------- | ------------------------------------------------------------------------ |
| `offsets`        | $V + 1$ | "Соседи вершины `i` лежат в `column_indices[offsets[i] : offsets[i+1]]`" |
| `column_indices` | $E$     | "Все соседи всех вершин, выписанные подряд"                              |
| `values`         | $E$     | "Веса тех же рёбер, параллельно `column_indices`"                        |

**Главная идея:** заменить множество маленьких объектов на несколько больших непрерывных массивов. Это даёт:

- ✅ Минимальный расход памяти (нет заголовков объектов)
- ✅ Отличную кеш-локальность (данные лежат рядом)
- ✅ Быстрый последовательный доступ (CPU предсказывает обращения)
- ✅ Простоту сериализации (просто три массива чисел)

**Когда использовать CSR:**

- Граф **большой** (миллионы вершин)
- Граф **статический** (не меняется, или меняется редко)
- Нужна **высокая производительность** обходов (BFS, DFS, PageRank)
- Важна **экономия памяти**

**Когда НЕ использовать CSR:**

- Граф **динамический** (часто добавляются/удаляются рёбра)
- Граф **плотный** (лучше матрица смежности)
- Граф **маленький** (накладные расходы не окупятся)
