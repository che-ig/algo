Законы булевой логики — это фундамент для работы с условиями в программировании (`if`, `while`, тернарные операторы и т.д.). Понимание этих законов помогает писать более чистый, читаемый и эффективный код, а также упрощать сложные конструкции.

В программировании (на примере синтаксиса C-подобных языков: Java, C++, JavaScript, C#) используются три базовые операции:

- **AND (И)**: `&&` (или `&`)
- **OR (ИЛИ)**: `||` (или `|`)
- **NOT (НЕ)**: `!`

Ниже приведены основные законы булевой алгебры с примерами того, как они выглядят в коде.

---

### 1. Законы де Моргана (Самые важные для рефакторинга)

Эти законы позволяют «раскрывать» отрицания. Они незаменимы, когда нужно упростить сложное условие с `!` (NOT).

- **Отрицание AND:** `!(A && B) == !A || !B`
  - _Пример:_ `if (!(user.isAdmin && user.isActive))`
  - _Упрощение:_ `if (!user.isAdmin || !user.isActive)`
- **Отрицание OR:** `!(A || B) == !A && !B`
  - _Пример:_ `if (!(status == "active" || status == "pending"))`
  - _Упрощение:_ `if (status != "active" && status != "pending")`

### 2. Законы поглощения (Absorption)

Позволяют убрать избыточные проверки, если одна из них уже включает в себя другую.

- **OR поглощение:** `A || (A && B) == A`
  - _Пример:_ `if (isReady || (isReady && isLoaded))`
  - _Упрощение:_ `if (isReady)` _(Если `isReady` истинно, то второе условие уже не важно)._
- **AND поглощение:** `A && (A || B) == A`
  - _Пример:_ `if (hasAccess && (hasAccess || isGodMode))`
  - _Упрощение:_ `if (hasAccess)`

### 3. Законы дистрибутивности (Распределительные)

Полезны для вынесения общих условий за скобки (факторизация кода).

- **AND через OR:** `A && (B || C) == (A && B) || (A && C)`
  - _Пример:_ `if (isPremium && (hasDiscount || hasBonus))`
  - _Альтернатива:_ `if ((isPremium && hasDiscount) || (isPremium && hasBonus))` _(Первый вариант читается лучше)._
- **OR через AND:** `A || (B && C) == (A || B) && (A || C)`

### 4. Законы нуля и единицы (Доминирования и Идентичности)

Описывают поведение при сравнении с константами `true` и `false`.

- `A && true == A` _(Истина не меняет результат AND)_
- `A && false == false` _(Ложь в AND всё превращает в ложь)_
- `A || true == true` _(Истина в OR всё превращает в истину)_
- `A || false == A` _(Ложь не меняет результат OR)_

### 5. Закон двойного отрицания

- `!(!A) == A`
  - _Пример:_ `if (!(!isEmpty))` -> `if (isEmpty)`
  - _Совет:_ Избегайте двойных отрицаний в коде (например, `isNotEmpty` вместо `!isEmpty`), так как они затрудняют чтение.

### 6. Коммутативность и Ассоциативность

- **Коммутативность (Переместительный):** Порядок не важен.
  - `A && B == B && A`
  - `A || B == B || A`
- **Ассоциативность (Сочетательный):** Скобки можно расставлять как угодно (если операторы одинаковые).
  - `(A && B) && C == A && (B && C)`
  - `(A || B) || C == A || (B || C)`

### 7. Идемпотентность

Повторная проверка одного и того же условия не меняет результат.

- `A && A == A`
- `A || A == A`
  - _Пример:_ `if (isValid && isValid)` всегда равносильно `if (isValid)`.

---

### ⚠️ Специфика программирования: «Короткое замыкание» (Short-Circuit)

В отличие от чистой математики, в программировании операторы `&&` и `||` вычисляются **лениво** (по короткой схеме). Это критически важно знать!

1.  **`A && B`**: Если `A` равно `false`, то `B` **не вычисляется**, так как результат уже гарантированно будет `false`.
    - _Зачем нужно:_ Защита от ошибок (Null Reference).
    - _Пример:_ `if (obj != null && obj.value > 0)`. Если `obj` равен `null`, вторая часть не выполнится, и программа не упадет с ошибкой.
2.  **`A || B`**: Если `A` равно `true`, то `B` **не вычисляется**, так как результат уже гарантированно `true`.
    - _Зачем нужно:_ Оптимизация и безопасность.
    - _Пример:_ `if (cache.hasData() || fetchFromNetwork())`. Если данные есть в кэше, тяжелый запрос в сеть не будет выполнен.

_(Примечание: в некоторых языках, например в Java или C#, есть побитовые операторы `&` и `|`, которые **всегда** вычисляют обе части. Их использование в логических условиях вместо `&&` и `||` часто является ошибкой или, наоборот, хитрым хаком, когда нужно гарантированно выполнить сайд-эффекты в обеих частях)._

### 💡 Практический пример рефакторинга

**Плохой код (сложно читать, есть избыточность):**

```javascript
if (!(user.age >= 18 && user.hasConsent) || user.isBot) {
  // deny access
}
if (user.isBot || (user.isBot && user.hasSpecialFlag)) {
  // ban user
}
```

**Хороший код (применены Законы де Моргана и Поглощения):**

```javascript
// Применили де Моргана: !(A && B) -> !A || !B
if (user.age < 18 || !user.hasConsent || user.isBot) {
  // deny access
}

// Применили поглощение: A || (A && B) -> A
if (user.isBot) {
  // ban user
}
```
