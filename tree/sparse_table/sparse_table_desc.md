# Sparse Table — структура данных для статических range-запросов

**Sparse table** (разреженная таблица) — это структура данных, которая позволяет отвечать на **запросы на отрезке** (range queries) за **O(1)** после предварительной обработки за **O(n log n)**.

Главное ограничение: массив **статический** — элементы нельзя изменять после построения.

## Основная операция

### 🎯 Range Query (запрос на отрезке) — O(1)

Запрос вида: _"Найди значение f(a[l], a[l+1], ..., a[r])"_.

Ключевая идея: любой отрезок длины `L` можно покрыть **двумя перекрывающимися** блоками длины `2^k`, где `k = floor(log2(L))`.

```
Отрезок [l, r]:  |----длина L----|
Блок 1:          |---2^k---|
Блок 2:                  |---2^k---|
```

Если операция `f` **идемпотентна** (т.е. `f(x, x) = x`), то перекрытие не влияет на результат.

## Какие операции поддерживает

### ✅ Идеально подходят (идемпотентные операции)

| Операция         | Описание                              |
| ---------------- | ------------------------------------- |
| `min`            | Минимум на отрезке                    |
| `max`            | Максимум на отрезке                   |
| `gcd`            | НОД на отрезке                        |
| `lcm`            | НОК на отрезке                        |
| `AND`            | Побитовое И                           |
| `OR`             | Побитовое ИЛИ                         |
| `bitwise AND/OR` | Любая идемпотентная бинарная операция |

Для всех этих операций: `f(x, x) = x`, поэтому перекрытие блоков безопасно.

### ⚠️ Частично подходят (неидемпотентные операции)

| Операция  | Комментарий                                                                                                                                        |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sum`     | Сумма — не идемпотентна (`x + x = 2x`). Но можно вычислить через **два непересекающихся** блока: `sum[l, r] = table[l][k] + table[r - 2^k + 1][k]` |
| `product` | Аналогично sum                                                                                                                                     |

### ❌ Не подходят

Операции, где важен **порядок** или **точная структура** отрезка:

- Поиск k-го элемента
- Подсчёт уникальных элементов
- Операции, зависящие от позиции

## Что Sparse Table НЕ умеет

### 🚫 Нет обновлений (update)

После построения **нельзя изменить** элемент массива. Если нужны обновления — используйте:

- **Segment Tree** — O(log n) на запрос и обновление
- **Fenwick Tree (BIT)** — для сумм/префиксных операций

## Сложности

| Операция   | Время                | Память     |
| ---------- | -------------------- | ---------- |
| Построение | O(n log n)           | O(n log n) |
| Запрос     | **O(1)**             | —          |
| Обновление | ❌ Не поддерживается | —          |

## Пример реализации (min на отрезке)

```python
import math

class SparseTable:
    def __init__(self, arr: list[int]) -> None:
        n: int = len(arr)
        if n == 0:
            self.table: list[list[int]] = []
            self.log: list[int] = []
            return

        # K = floor(log2(n)) + 1 — максимальная степень двойки
        k: int = math.floor(math.log2(n)) + 1

        # table[j][i] = min на отрезке [i, i + 2^j - 1]
        self.table: list[list[int]] = [[0] * n for _ in range(k)]
        self.table[0] = arr[:]  # База: блоки длины 2^0 = 1

        # Заполняем таблицу по возрастанию степени
        for j in range(1, k):
            step: int = 1 << j  # 2^j
            half: int = 1 << (j - 1)  # 2^(j-1)
            for i in range(n - step + 1):
                self.table[j][i] = min(
                    self.table[j - 1][i],
                    self.table[j - 1][i + half]
                )

        # Предподсчитанные логарифмы для O(1) запроса
        self.log: list[int] = [0] * (n + 1)
        for i in range(2, n + 1):
            self.log[i] = self.log[i // 2] + 1

    def query(self, l: int, r: int) -> int:
        """Запрос минимума на отрезке [l, r] за O(1)."""
        length: int = r - l + 1
        k: int = self.log[length]
        # Два перекрывающихся блока длины 2^k
        return min(
            self.table[k][l],
            self.table[k][r - (1 << k) + 1]
        )
```

## Расширение: Disjoint Sparse Table

Если нужна **неидемпотентная** операция (например, сумма, произведение, конкатенация строк), существует модификация — **Disjoint Sparse Table**:

- Строится за O(n log n)
- Запрос за **O(1)**
- Блоки **не перекрываются** — результат точный
- Требует больше памяти и сложнее в реализации

## Когда использовать Sparse Table

✅ **Используйте**, если:

- Массив **статический** (нет обновлений)
- Много запросов на отрезках
- Операция идемпотентна (min/max/gcd)
- Нужен O(1) на запрос

❌ **Не используйте**, если:

- Нужны обновления элементов → берите Segment Tree
- Операция не ассоциативна или не идемпотентна (без disjoint-версии)
- Память критична — O(n log n) может быть много

## Сравнение с альтернативами

| Структура          | Построение | Запрос   | Обновление | Память     |
| ------------------ | ---------- | -------- | ---------- | ---------- |
| **Sparse Table**   | O(n log n) | **O(1)** | ❌         | O(n log n) |
| Segment Tree       | O(n)       | O(log n) | O(log n)   | O(n)       |
| Fenwick Tree       | O(n)       | O(log n) | O(log n)   | O(n)       |
| Sqrt-decomposition | O(n)       | O(√n)    | O(1)       | O(n)       |

**Итог:** Sparse Table — это инструмент для **быстрых запросов на статических данных** с идемпотентными операциями. Её главная сила — константное время ответа, что делает её незаменимой в задачах типа RMQ (Range Minimum Query).
