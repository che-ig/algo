# Как работает LCA, когда оба узла в одном поддереве

Отличный вопрос! Это один из самых интересных случаев. Давайте разберём его детально.

---

## Восстановим дерево с картинки

```text
              A (root)
             / \
            B   C
           /
          D  ← node_p
         / \
        E   F
       /   / \
      G   H   I
     /
    J
   /
  K  ← node_q
```

Здесь `node_p = D`, `node_q = K`. Узел `D` является **предком** узла `K`.

---

## Пошаговая трассировка рекурсии

```python
def LCA(root, p, q):
    if root is None or root == p or root == q:
        return root
    left = LCA(root.left, p, q)
    right = LCA(root.right, p, q)
    if left and right:
        return root
    return left or right
```

### Шаг 1: `LCA(A, D, K)`

```text
A не равен D и не равен K → идём в детей
├── left = LCA(B, D, K)    ← ищем в левом поддереве
└── right = LCA(C, D, K)   ← ищем в правом поддереве
```

### Шаг 2: `LCA(C, D, K)` — правое поддерево A

```text
C ≠ D, C ≠ K
├── left = LCA(None, D, K) → None
└── right = LCA(None, D, K) → None

Оба None → return None
```

**Результат:** `right = None` для узла A.

### Шаг 3: `LCA(B, D, K)` — левое поддерево A

```text
B ≠ D, B ≠ K
├── left = LCA(D, D, K)    ← нашли p!
└── right = LCA(None, D, K) → None
```

### Шаг 4: `LCA(D, D, K)` — БАЗОВЫЙ СЛУЧАЙ! 🔑

```text
D == p → return D  ← СРАЗУ ВОЗВРАЩАЕМ, НЕ ИДЁМ В ДЕТЕЙ!
```

**Это ключевой момент!** Мы нашли `node_p` и **не спускаемся дальше** к `node_q`. Мы просто говорим: "Здесь есть один из искомых узлов, возвращаю его наверх".

### Шаг 5: Возврат к узлу B

```text
left = D   (вернулось из LCA(D, D, K))
right = None

left ≠ None, right = None → return left = D
```

### Шаг 6: Возврат к узлу A

```text
left = D   (вернулось из LCA(B, D, K))
right = None (вернулось из LCA(C, D, K))

left ≠ None, right = None → return left = D
```

---

## Итог: `LCA(A, D, K) = D` ✅

**Узел D (node_p) и есть наименьший общий предок**, потому что:

- `D` — предок самого себя (по определению LCA)
- `D` — предок `K` (путь: D → E → G → J → K)
- Нет узла ниже `D`, который был бы предком обоих

---

## Визуализация потока возврата

```text
LCA(A)
├── LCA(B)
│   ├── LCA(D) ← БАЗОВЫЙ СЛУЧАЙ: D == p → return D 🎯
│   │   (мы НЕ спускаемся к K! Не нужно!)
│   └── LCA(None) → None
│   → return D
└── LCA(C)
    ├── LCA(None) → None
    └── LCA(None) → None
    → return None
→ return D  ✅
```

---

## Почему мы не спускаемся к node_q?

Это **самая важная часть** понимания алгоритма. Когда мы доходим до `node_p`:

```python
if root == p or root == q:
    return root  ← ВОЗВРАЩАЕМ СРАЗУ, не глядя на детей
```

**Почему это корректно?**

Потому что если `node_q` находится **в поддереве** `node_p`, то `node_p` автоматически является предком `node_q`. Значит, `node_p` и есть LCA — нет смысла искать дальше.

**Три возможных случая, когда мы нашли p или q:**

| Случай | Где второй узел?           | Что возвращаем?                          | Почему?                                            |
| ------ | -------------------------- | ---------------------------------------- | -------------------------------------------------- |
| 1      | В поддереве текущего узла  | **Текущий узел**                         | Он предок обоих                                    |
| 2      | В другом поддереве         | **Текущий узел** (позже, на уровне выше) | Родитель объединит left и right                    |
| 3      | Вообще не в этом поддереве | **Текущий узел** (всплывёт наверх)       | Если второй узел найден где-то ещё, LCA будет выше |

---

## Контрпример: что если бы мы спустились к K?

Представьте "неправильную" версию алгоритма, которая не останавливается на `p`:

```python
# ❌ НЕПРАВИЛЬНО
def LCA_wrong(root, p, q):
    if root is None:
        return None

    left = LCA_wrong(root.left, p, q)
    right = LCA_wrong(root.right, p, q)

    # Проверяем, содержит ли поддерево p или q
    has_p = (root == p) or (left == p) or (right == p)
    has_q = (root == q) or (left == q) or (right == q)

    if has_p and has_q:
        return root
    if has_p:
        return p
    if has_q:
        return q
    return None
```

Эта версия тоже дала бы правильный ответ `D`, но:

- ❌ Обходит **всё** поддерево `D`, включая путь до `K`
- ❌ Делает лишнюю работу
- ❌ Сложнее для понимания

**Правильный алгоритм** останавливается сразу, как находит `p` или `q`, потому что этого **достаточно** для корректного ответа.

---

## Мнемоника для запоминания

> **"Нашёл p или q — сразу возвращай. Не нужно искать второй узел в поддереве — если он там есть, текущий узел уже является LCA."**

Или ещё короче:

> **"LCA — это первый узел, из которого 'видны' оба p и q. Если мы в p и q находится ниже — мы уже в LCA."**

---

## Связь с тремя случаями LCA

В задаче LCA всегда один из трёх случаев:

### Случай 1: p и q в разных поддеревьях

```text
        LCA
       /   \
      p     q
```

→ `left = p`, `right = q`, оба ≠ None → **return LCA**

### Случай 2: q в поддереве p (наш случай!)

```text
        LCA = p
       /
      ...
       \
        q
```

→ На уровне `p`: `root == p` → **return p сразу**

### Случай 3: p в поддереве q (симметрично случаю 2)

```text
        LCA = q
       /
      ...
       \
        p
```

→ На уровне `q`: `root == q` → **return q сразу**

---

## Ключевой takeaway

**Когда оба узла в одном поддереве, алгоритм работает так:**

1. Спускаемся вниз, пока не найдём **первый** из узлов (p или q)
2. Как только нашли — **сразу возвращаем его наверх**
3. Второй узел может быть где угодно в поддереве первого — это не важно
4. На уровне выше: одно поддерево вернуло найденный узел, другое — None
5. Правило `return left or right` передаёт найденный узел дальше наверх
6. В итоге корень возвращает тот узел (p или q), который был найден **первым при спуске** — и это и есть LCA

В нашем примере: первым при спуске встретился `D` (node_p), поэтому `D` и возвращается как ответ. `K` (node_q) вообще не посещается — и это **правильно**, потому что `D` уже является предком `K`. 👍
