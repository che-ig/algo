## Подробное объяснение строки

```python
if i > 0 and nums[i] == nums[i - 1] and not (mask & (1 << (i - 1))):
    valid = False
    break
```

### Что проверяет эта строка

Она срабатывает (делает маску невалидной), когда **одновременно** выполнены три условия:

1. `i > 0` — у текущего элемента есть предыдущий (защита от `i-1 = -1`).
2. `nums[i] == nums[i - 1]` — текущий элемент является дубликатом предыдущего (массив отсортирован, поэтому дубликаты стоят рядом).
3. `not (mask & (1 << (i - 1)))` — **бит предыдущего дубликата НЕ установлен** в маске, то есть предыдущий такой же элемент мы НЕ берём.

Смысл: «мы хотим взять `i`-й дубликат, но при этом не взяли предыдущий такой же элемент». Именно такую ситуацию и надо запретить.

### Разбор `mask & (1 << (i - 1))`

- `1 << (i - 1)` — число, у которого установлен только бит с номером `i-1`. Например, при `i = 2`: `1 << 1 = 0b10`.
- `mask & (1 << (i - 1))` — побитовое И. Результат равен `0`, если бит `i-1` в маске **не установлен**; иначе — ненулевое число.
- `not (...)` — превращает это в `True`, когда бит **не установлен**, и в `False`, когда установлен.

Итого `not (mask & (1 << (i - 1)))` означает буквально: **«бит предыдущего дубликата не установлен»**.

### Зачем это нужно: свойство «префикса»

После сортировки одинаковые значения образуют группы подряд идущих позиций, скажем `i1 < i2 < ... < ik`. Все элементы в группе равны, поэтому с точки зрения итогового подмножества **неважно, какие именно из них мы взяли** — важно только их количество.

Чтобы каждое уникальное подмножество порождалось **ровно одной** маской, договоримся: внутри каждой группы дубликатов мы берём **префикс** этой группы. То есть либо первые `0`, либо первые `1`, либо первые `2`, … элементов, без «дырок».

Проверка `nums[i] == nums[i-1] and not bit(i-1)` — это и есть локальный тест на «дырку»:

- Если бит `i` установлен (мы берём `i`-й элемент группы),
- но бит `i-1` не установлен (предыдущий элемент группы не берём),
- значит, в группе есть «дырка»: взяли более поздний, но пропустили более ранний. Это нарушает свойство префикса → маску отбрасываем.

Достаточно проверять только **непосредственного предшественника** `i-1`, потому что мы идём по `i` слева направо. Если бы была дырка раньше (например, бит `i-2` не установлен, а `i-1` установлен), она была бы поймана на шаге `i-1`, когда мы обрабатывали предыдущий элемент. Так что индуктивно все более ранние «дырки» уже отфильтрованы.

### Полный разбор на `nums = [1, 2, 2]`

Индексы `0, 1, 2`; группа дубликатов — позиции `1` и `2` (оба `2`).

| mask  | биты  | подмножество | что происходит на шаге `i`                                                                                 |
| ----- | ----- | ------------ | ---------------------------------------------------------------------------------------------------------- |
| `000` | –     | `[]`         | нет установленных битов — валидно                                                                          |
| `001` | 0     | `[1]`        | `i=0`: нет предыдущего                                                                                     |
| `010` | 1     | `[2]`        | `i=1`: `nums[1]=2 ≠ nums[0]=1` — проверка не срабатывает, валидно                                          |
| `011` | 0,1   | `[1,2]`      | `i=1` — не дубликат; валидно                                                                               |
| `100` | 2     | `[2]`        | `i=2`: `nums[2]=2 == nums[1]=2`, бит `1` в маске? `0b100 & 0b010 = 0` → не установлен → **невалидно**      |
| `101` | 0,2   | `[1,2]`      | `i=2`: то же, бит `1` не установлен → **невалидно**                                                        |
| `110` | 1,2   | `[2,2]`      | `i=2`: `nums[2]=2 == nums[1]=2`, бит `1` установлен (`0b110 & 0b010 = 0b010 ≠ 0`) → условие ложно, валидно |
| `111` | 0,1,2 | `[1,2,2]`    | `i=2`: бит `1` установлен → валидно                                                                        |

Отброшенные маски `100` и `101` дали бы `[2]` и `[1,2]`, которые уже были получены масками `010` и `011`. Именно это и нужно — каждое подмножество ровно один раз.

### Аналогия

Представьте, что у вас три одинаковые красные кнопки, и вам нужно выбрать «сколько красных нажать». Очевидно, что вариантов ровно 4: 0, 1, 2, 3 кнопки. Но если нумеровать кнопки, то «нажать одну» можно тремя способами (кнопку 1, 2 или 3) — все они дают одно и то же. Правило `not bit(i-1)` говорит: «нажимайте красные кнопки по порядку слева направо, без пропусков». Тогда «нажать одну» — это всегда «нажать первую», и вариант ровно один.

### Что было бы, если убрать это условие

Без него bitmask перебирал бы все `2^n` масок, и при дубликатах в ответ попадали бы копии. Пришлось бы либо дедуплицировать через `set` (вариант 1 из предыдущего ответа), либо как-то иначе. Данное условие — это способ получить уникальность «бесплатно», прямо в процессе перебора, не тратя память на `set`.
