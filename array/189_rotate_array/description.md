## Оптимальное решение задачи Rotate Array

### 🧠 Подход и идея алгоритма

Для данной задачи существует несколько подходов, но **наиболее оптимальным** с точки зрения баланса времени и памяти является метод **трёх обратных разворотов** (three-way reversal). Он позволяет выполнить поворот **in-place** (за O(1)O(1)O(1) дополнительной памяти) за O(n)O(n)O(n) времени.

Идея основана на следующем математическом свойстве массивов: Поворот массива вправо на `k` шагов эквивалентен:

1. Полному реверсу исходного массива.
2. Реверсу первых `k` элементов.
3. Реверсу оставшихся `n - k` элементов.

**Почему это работает?**  
Представьте, что массив состоит из двух частей: `A` (первые `n-k` элементов) и `B` (последние `k` элементов). Исходный массив: `[A | B]`.

- После полного реверса: `[B^R | A^R]` (где `^R` означает реверс).
- После реверса первой части: `[B | A^R]`.
- После реверса второй части: `[B | A]` — что и является результатом поворота вправо на `k`.

---

### 💻 Реализация на Python

```python
from typing import List

def rotate(nums: List[int], k: int) -> None:
    """
    Поворачивает массив nums вправо на k шагов на месте.
    Не возвращает ничего, так как модификация происходит in-place.
    """
    n = len(nums)
    if n == 0:
        return

    # k может быть больше длины массива, поэтому берём остаток от деления.
    # Это корректно обрабатывает циклический характер поворота.

    k = k % n

    # Если k = 0 или k кратно n, поворот не меняет массив.

    if k == 0:
        return

    # Вспомогательная функция для реверса части массива

    def reverse(start: int, end: int) -> None:
        while start < end:
            nums[start], nums[end] = nums[end], nums[start]
            start += 1
            end -= 1


    # Шаг 1: Реверс всего массива
    reverse(0, n - 1)

    # Шаг 2: Реверс первых k элементов
    reverse(0, k - 1)

    # Шаг 3: Реверс оставшихся n - k элементов
    reverse(k, n - 1)
```

---

### 🔍 Пошаговый разбор на примере 1

**Вход:** `nums = [1, 2, 3, 4, 5, 6, 7]`, `k = 3`

1. `n = 7`, `k = 3 % 7 = 3`
2. `reverse(0, 6)` → `[7, 6, 5, 4, 3, 2, 1]`
3. `reverse(0, 2)` → `[5, 6, 7, 4, 3, 2, 1]`
4. `reverse(3, 6)` → `[5, 6, 7, 1, 2, 3, 4]` **Результат:** `[5, 6, 7, 1, 2, 3, 4]` ✅

### 📊 Анализ сложности

|Метрика|Значение|Обоснование|
|---|---|---|
|**Время**|O(n)O(n)O(n)|Каждый элемент массива участвует ровно в двух обменах (реверсах). Линейная зависимость от длины массива.|
|**Память**|O(1)O(1)O(1)|Алгоритм работает **in-place**. Используется только несколько переменных-указателей (`start`, `end`, `n`, `k`).|

---

### 🛡️ Обработка краевых случаев (Edge Cases)

1. **`k >= n`**: Операция `k = k % n` гарантирует, что мы не выйдем за границы массива и учтём циклическую природу поворота. Например, поворот `[1, 2]` на 5 шагов эквивалентен повороту на 5%2=15 \% 2 = 15%2=1 шаг.
2. **`k = 0` или `k % n == 0`**: Добавлена проверка `if k == 0: return` для пропуска лишних операций и оптимизации.
3. **`n = 1`**: Массив из одного элемента не меняется, код корректно обрабатывает это через логику реверса (цикл `while start < end` просто не выполнится).
4. **Отрицательные числа**: Алгоритм оперирует только индексами, поэтому значения элементов не влияют на логику. Пример 2 будет обработан идентично.

### ⚖️ Сравнение с альтернативным подходом (срез)

В Python часто хочется написать `nums[:] = nums[-k:] + nums[:-k]`. **Почему это менее оптимально:**

- **Время:** O(n)O(n)O(n) — приемлемо.
- **Память:** O(n)O(n)O(n) — создаются два новых списка (среза), что нарушает требование O(1)O(1)O(1) дополнительной памяти. В производственном коде с большими массивами это может привести к лишним нагрузкам на сборщик мусора (GC) и увеличению пикового потребления RAM.
- **Читаемость и контроль:** Метод трёх реверсов демонстрирует глубокое понимание работы с памятью и индексами, что ценится на технических интервью и в системном программировании.
